==================================================

HighLevel остаётся CRM/source of truth.

Токены имеют права чтения.

СТРОГО ЗАПРЕЩЕНО:
- отправлять SMS/Email/WhatsApp
- создавать/закрывать Tasks
- менять Contacts
- менять Opportunities/Stages

- менять Tags/Custom Fields
- менять Appointments
- делать любые POST/PATCH/PUT/DELETE в HighLevel

Разрешены только GET/read запросы.

Проверь весь `src/services/ghl.ts`: в production коде не должно быть ни одного HighLevel write endpoint.

НЕ делай тестовые сообщения реальным клиентам.

5. SALES ROUTING
==================================================

Критическая логика:

Дмитрий + Kate/AstraGlo
→ получают ВСЕ релевантные события.

Каждый Sales
→ получает ТОЛЬКО события клиентов/Opportunity, где HighLevel assigned user совпадает с его GHL User ID для конкретного Location.

Mapping:
Telegram Sales user_id ↔ WallPanels GHL User ID ↔ Verona GHL User ID.

Если lead unassigned или mapping не найден:
→ только admins.

Не отправляй чужие lead events другому sales.

==================================================
9. GHL WEBHOOKS + POLLING FALLBACK
==================================================

Код уже поддерживает два режима:

A) HighLevel Webhooks — основной real-time путь.
B) READ-ONLY polling — fallback, чтобы бот работал даже до ручной настройки workflow webhooks.

Оставь `POLLING_ENABLED=true` на первом deploy.

Polling не должен сканировать всю историю CRM.
Он должен брать только свежие сообщения с небольшим overlap и dedupe в Neon.

После deploy дай Дмитрию точные URL:

`{PUBLIC_BASE_URL}/webhooks/highlevel/customer-replied?secret=...&locationId={{location.id}}&contactId={{contact.id}}`

`{PUBLIC_BASE_URL}/webhooks/highlevel/transcript-generated?secret=...&locationId={{location.id}}&contactId={{contact.id}}`

Также optional:
- `/webhooks/highlevel/task-reminder`
- `/webhooks/highlevel/appointment-reminder`

`GHL_WEBHOOK_SHARED_SECRET` сгенерируй, если его нет, и сохрани ТОЛЬКО в Railway ENV.

Не пытайся создавать/редактировать HighLevel workflows через read-only API или внутренние undocumented API.
Если у тебя нет разрешённого GUI-доступа — просто дай Дмитрию готовые URL и точные шаги из `docs/HIGHLEVEL_WEBHOOK_SETUP.md`.

10. WORK HOURS
==================================================

Используй настройки из Word.
Если там нет значений:
TIMEZONE=America/New_York
WORK_START=08:45
WORK_END=20:00
WORK_DAYS=1,2,3,4,5,6
DAILY_BRIEF_TIME=08:45

Вне рабочего времени event сохраняется, Telegram notification откладывается до следующего рабочего старта.
